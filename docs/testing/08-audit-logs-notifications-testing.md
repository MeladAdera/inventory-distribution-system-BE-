# How to Test: Audit Logs & Notifications

## Prerequisites

1. Docker running: `docker compose up -d`
2. Migrations applied: `npm run migration:run`
3. App running: `npm run start:dev`
4. Complete `07-orders-testing.md` first — audit logs and notifications are generated by inventory and order operations, so you need existing data

---

## Part 1 — Audit Logs

### Step 1 — List all audit logs (admin)

```bash
curl "http://localhost:3000/audit-logs" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: paginated list of all audit rows created during inventory and order testing. You should see `STOCK_IN`, `ADJUSTMENT`, `TRANSFER_OUT`, `TRANSFER_IN`, and `STATUS_CHANGED` entries.

---

### Step 2 — Filter by type

```bash
curl "http://localhost:3000/audit-logs?type=INVENTORY" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

curl "http://localhost:3000/audit-logs?type=ORDER" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: only rows with the matching `type`.

---

### Step 3 — Filter by action

```bash
curl "http://localhost:3000/audit-logs?action=STOCK_IN" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

curl "http://localhost:3000/audit-logs?action=STATUS_CHANGED" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

curl "http://localhost:3000/audit-logs?action=TRANSFER_OUT" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

---

### Step 4 — Filter by shop

```bash
# Warehouse shop logs
curl "http://localhost:3000/audit-logs?shopId=1" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Specific shop logs
curl "http://localhost:3000/audit-logs?shopId=2" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

---

### Step 5 — Filter by date range

```bash
curl "http://localhost:3000/audit-logs?fromDate=2026-06-01&toDate=2026-06-30" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: only logs created within June 2026.

---

### Step 6 — Combine filters

```bash
curl "http://localhost:3000/audit-logs?type=INVENTORY&action=TRANSFER_OUT&shopId=1" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: only warehouse TRANSFER_OUT logs — one per order item that was received.

---

### Step 7 — Filter by entityType and entityId

```bash
curl "http://localhost:3000/audit-logs?entityType=inventory&entityId=1" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: all audit rows that touched inventory record with id=1.

---

### Step 8 — Pagination

```bash
curl "http://localhost:3000/audit-logs?page=1&limit=3" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: at most 3 results, with `totalPages`, `hasNext`, `hasPrev` populated correctly.

---

### Step 9 — Get single audit log

```bash
# Use an id from the list above
curl "http://localhost:3000/audit-logs/1" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: single audit log object.

```bash
# Non-existent id
curl "http://localhost:3000/audit-logs/9999" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: `404 Audit log not found`.

---

### Step 10 — Authorization: shop owner sees only own shop

```bash
curl "http://localhost:3000/audit-logs" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: only logs where `shop_id` matches the owner's shop.

```bash
# Try to scope to a different shop — should be silently overridden
curl "http://localhost:3000/audit-logs?shopId=1" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: same result as above — warehouse logs are NOT returned. The `shopId` param is ignored for non-admins.

---

### Step 11 — Authorization: shop owner cannot read another shop's log

```bash
# Find a log that belongs to shop_id=1 (warehouse)
# Then try to fetch it as a shop owner
curl "http://localhost:3000/audit-logs/1" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: `403 Forbidden`.

## Part 2 — Notifications

### Step 12 — Check warehouse notifications (order created trigger)

Every `POST /orders` creates an `ORDER_CREATED` notification in the warehouse feed.

```bash
curl "http://localhost:3000/notifications" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: notifications with `type: "ORDER_CREATED"` and titles like `"New Order #1"`.

---

### Step 13 — Check shop notifications (status changed trigger)

Every `PATCH /orders/:id/status` creates an `ORDER_STATUS` notification for the requesting shop.

```bash
curl "http://localhost:3000/notifications" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: notifications with `type: "ORDER_STATUS"` and messages like:
- `"Order #1 is now PROCESSING."`
- `"Order #1 is now SHIPPED."`
- `"Order #1 is now RECEIVED."`
- `"Order #1 is now COMPLETED."`

---

### Step 14 — Filter unread notifications

```bash
curl "http://localhost:3000/notifications?isRead=false" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: only notifications where `is_read: false`.

```bash
curl "http://localhost:3000/notifications?isRead=true" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: only notifications where `is_read: true` (empty if none have been read yet).

---

### Step 15 — Mark a single notification as read

```bash
# Use an id from the list above
curl -X PATCH "http://localhost:3000/notifications/1/read" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: `{ "success": true }`.

```bash
# Verify it no longer appears in unread
curl "http://localhost:3000/notifications?isRead=false" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: notification with id=1 is gone from the unread list.

---

### Step 16 — Mark a notification from another shop — 404

```bash
# Try to mark a warehouse notification (id from admin feed) as read using owner token
curl -X PATCH "http://localhost:3000/notifications/1/read" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: `404 Notification not found` — the `shop_id` check prevents cross-shop access.

---

### Step 17 — Mark all as read

```bash
curl -X PATCH "http://localhost:3000/notifications/read-all" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: `{ "success": true }`.

```bash
# Verify all are now read
curl "http://localhost:3000/notifications?isRead=false" \
  -H "Authorization: Bearer $OWNER_TOKEN"
```

Expected: `total: 0`, empty `data` array.

---

### Step 18 — Trigger a low-stock notification

Stock in a product with a very small quantity (below the default threshold of 10).

```bash
curl -X POST "http://localhost:3000/inventory/stock-in" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"productId": 1, "quantity": 5}'
```

Expected: inventory record with `is_low_stock: true`.

```bash
# Check warehouse notifications — LOW_STOCK should have appeared
curl "http://localhost:3000/notifications?isRead=false" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: one notification with `type: "LOW_STOCK"` and title like `"Low Stock: Coca Cola 330ml"`.

---

### Step 19 — Low-stock de-duplication (no spam)

Do another stock-in or adjustment while the LOW_STOCK notification is still unread.

```bash
curl -X PATCH "http://localhost:3000/inventory/1" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"adjustment": -1}'
```

```bash
curl "http://localhost:3000/notifications?isRead=false&type=LOW_STOCK" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: **still only one** LOW_STOCK notification — no duplicate was created because the previous one is unread.

---

### Step 20 — Low-stock resets after reading

Mark the LOW_STOCK notification as read, then trigger another adjustment.

```bash
# Get the LOW_STOCK notification id
curl "http://localhost:3000/notifications" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Mark it read
curl -X PATCH "http://localhost:3000/notifications/{id}/read" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Trigger another adjustment
curl -X PATCH "http://localhost:3000/inventory/1" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"adjustment": -1}'

# Check again
curl "http://localhost:3000/notifications?isRead=false" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Expected: a **new** LOW_STOCK notification appears because the previous one was acknowledged.
